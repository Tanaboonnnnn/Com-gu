# ComGu v3.1.0

v3.1.0 เป็นรอบที่ทำให้ขอบเขต workspace ของ Multi-agent กลายเป็น security boundary จริง ไม่ใช่แค่ข้อมูลว่าแต่ละ worker “ควร” ทำงานที่ไหน

## 3.1.0

### Highlights

- แต่ละ Run เลือก **Primary folder** และ **Shared folders** จาก approved roots ที่ผู้ใช้เพิ่มไว้แล้วเท่านั้น Prime ได้ scope ของ Run ทั้งชุด ส่วน Worker รับชุดเดิมหรือ subset ที่แคบกว่าได้ แต่ขยายสิทธิ์เองไม่ได้
- File tools ทุกตัวใน active Run ใช้ effective WorkspaceScope ของ caller เป็น authority เดียว รวมถึง read/search/image/patch/cwd และ shell-patch interception
- บน Windows, Run-scoped terminal ใช้ **MXC ProcessContainer** จำกัดทั้ง process tree ที่ระดับ OS การอ่าน/เขียนนอก scope, nested shell, child process, redirect, environment expansion, junction/reparse และ PTY ถูกใช้เป็น release-gate tests
- ถ้า Windows host ยังเตรียมไม่พร้อมหรือยืนยัน backend ไม่ได้ ComGu จะ **fail closed** และไม่ fallback ไปเปิด terminal แบบ unrestricted
- หน้า Chat แสดง RunId แบบสั้น, scope ของ Prime/Worker, ตัวเลือก scope สำหรับ Run ถัดไป และสถานะ command sandbox; ตัวเลือกทั้งหมดใช้ชื่อ root ที่อนุมัติแล้ว ไม่มีช่องส่ง arbitrary host path เข้า Run authority
- เพิ่ม **System Health v1** แยก Desktop, MCP Core, Tunnel, Browser bridge, Extension, Prime และ Workers ด้วย state ชุดเดียวกัน
- เพิ่ม **Recovery Manager v1** สำหรับ action ที่ย้อนกลับได้เท่านั้น พร้อมเช็ก RunId + scope fingerprint ก่อนและหลัง action และมี retry/backoff แบบมีขอบเขต

### Windows command sandbox preparation

บางเครื่องที่ MXC ต้องใช้ AppContainer+DACL fallback จะเห็นปุ่ม **Prepare Windows host** ขั้นตอนนี้ต้องให้ผู้ใช้กดเองและยืนยัน UAC ชัดเจน ComGu จะไม่ยกระดับสิทธิ์หรือแก้ host preparation อัตโนมัติระหว่าง build, test, startup หรือการ spawn command ปกติ

ถ้ายังไม่ prepare ระบบจะแสดง command sandbox ว่ายังไม่พร้อมและปิด Run-scoped command ไว้ก่อน File WorkspaceScope ยังทำงานตามปกติ

### หมายเหตุสำหรับ macOS

ComGu v3.1.0 บน macOS ยังไม่ได้เซ็นด้วย Developer ID และยังไม่ผ่าน Apple notarization หลังดาวน์โหลดจาก GitHub แล้ว macOS บางเครื่องจึงอาจขึ้นข้อความว่า `ComGu is damaged and can’t be opened` ทั้งที่ไฟล์ดาวน์โหลดมาครบ

ถ้าใช้ Mac ชิป Apple Silicon (M1/M2/M3/M4) ให้ดาวน์โหลด `ComGu-macOS-arm64.dmg` แล้วลาก `ComGu.app` เข้าโฟลเดอร์ `Applications` จากนั้นเปิด Terminal และรันคำสั่งนี้หนึ่งครั้ง:

```bash
xattr -dr com.apple.quarantine /Applications/ComGu.app && open /Applications/ComGu.app
```

คำสั่งนี้จะลบ quarantine attribute ที่ macOS ใส่ให้แอปที่ดาวน์โหลดจากอินเทอร์เน็ต แล้วเปิด ComGu ต่อทันที ถ้าติดตั้ง ComGu เวอร์ชันใหม่ในภายหลัง อาจต้องรันคำสั่งนี้อีกครั้งกับแอปชุดใหม่

> ใช้วิธีนี้เฉพาะกับ ComGu ที่ดาวน์โหลดจาก GitHub Release หน้านี้เท่านั้น ถ้ารุ่นถัดไปเพิ่ม Developer ID signing และ Apple notarization แล้ว ขั้นตอนนี้จะไม่จำเป็นอีก

### Platform notes

- Windows x64 เป็น primary confinement target และมี adversarial + packaged outside-scope denial gate ใน release pipeline
- macOS/Linux ยังไม่มี Run command-confinement backend ที่พิสูจน์แล้ว จึง fail closed สำหรับ Run-scoped commands แทนการลดระดับความปลอดภัย ส่วน file WorkspaceScope ยังใช้งานได้
- Windows Desktop automation (`observe`, `computer`) ยังเป็น Windows-only และไม่ได้ถูกจำกัดด้วย WorkspaceScope
- macOS release รองรับ Apple Silicon และต้องใช้ macOS 12 Monterey หรือใหม่กว่า
- Linux AppImage ยังมี electron-builder static-launcher fallback เป็น `--no-sandbox` เมื่อ host ปิด unprivileged user namespaces; ถ้าไม่ต้องการ fallback นี้ แนะนำใช้ DEB
- Release binaries ยัง **unsigned** และ macOS artifacts ยัง **unnotarized** จึงอาจเจอ Windows SmartScreen หรือ macOS Gatekeeper warning

### Safety

Run scope ไม่ได้เปลี่ยน arbitrary path ให้กลายเป็นสิทธิ์ใหม่ ผู้ใช้ต้อง approve root ก่อนเสมอ และ renderer ส่งเข้า Run ได้เฉพาะชื่อ root ที่มีอยู่แล้ว

Terminal session ที่ผูกกับ RunId/scope เก่าจะถูกปฏิเสธและ terminate เมื่อ authority เปลี่ยน รวมถึง process ที่เปิดไว้ก่อนเริ่ม Run แล้วพยายามใช้ต่อหลัง Run ได้ scope ใหม่

> ComGu v3.1.0 ยังเป็น beta สำหรับใช้งานในกลุ่ม Browser-side integration อาจต้องปรับตามการเปลี่ยนแปลงของ ChatGPT web UI และควรใช้กับงานที่มี version control/backup เสมอ
