# ComGu v3.1.1

## 3.1.1

ComGu 3.1.1 makes Workspace selection explicit per ChatGPT conversation and surfaces the existing Sub-agent switch directly in the top header.

### Highlights
- Workspace authority is keyed to the exact ChatGPT conversation when the extension can prove that identity. Each chat can select multiple approved roots, shown by friendly names only.
- The extension adds a compact workspace pill near the composer. Click it to choose the Primary/Shared approved roots for that chat.
- Without an exact extension Chat ID, ordinary file/terminal calls fail closed until the user explicitly selects approved roots in Desktop. That unidentified fallback is non-durable and cannot create Prime or Worker authority.
- Fresh Prime Runs inherit the current chat's workspace as an immutable ceiling. Workers can inherit or narrow only; they cannot add roots.
- The header order is Update -> Sub-agent -> Language -> Theme -> Status -> Power, and the Sub-agent switch uses the existing multi-agent setting.
- Connected/Not connected status now follows the current live connection state in both English and Thai.
- Root rename/remove handling keeps authority bound to root identity and prevents remove/re-add from silently resurrecting old access.
- Compact & Resume transfers exact per-chat workspace selection to the replacement conversation.

### Security model
No selected scope means no file/terminal authority. Native paths remain in the Desktop main process; extension/renderer surfaces use approved root names/ids only. Model arguments cannot widen authority. Existing v3.1.0 Windows MXC ProcessContainer confinement, fail-closed behavior, and explicit host-preparation rules are preserved.

### Platform notes
- Windows x64 remains the primary command-confinement target with adversarial and packaged outside-scope denial gates.
- macOS/Linux Run-scoped commands fail closed until a proven process-filesystem confinement backend exists; file workspace enforcement remains available.
- Windows Desktop automation remains a desktop-wide capability and is not constrained by Workspace roots.
- Release binaries are unsigned, and macOS artifacts are unnotarized. Windows SmartScreen or macOS Gatekeeper may warn on first launch.
