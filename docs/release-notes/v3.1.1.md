# ComGu v3.1.1

ComGu 3.1.1 ปรับระบบ Workspace ให้ผูกสิทธิ์กับแต่ละแชตของ ChatGPT โดยตรง และนำสวิตช์ Sub-agent ที่มีอยู่แล้วขึ้นมาไว้บนแถบด้านบน เพื่อให้เห็นและเปลี่ยนสถานะได้ง่ายขึ้น

## 3.1.1

### มีอะไรเปลี่ยนบ้าง

- แต่ละแชตเลือก Workspace ของตัวเองได้จาก approved roots ที่เพิ่มไว้ใน ComGu แล้ว รองรับ Primary folder และ Shared folders หลายโฟลเดอร์ หน้าเว็บเห็นเฉพาะชื่อที่ตั้งไว้ ไม่เห็นพาธจริงบนเครื่อง
- หน้า ChatGPT มีปุ่ม Workspace ขนาดเล็กอยู่ใกล้ช่องพิมพ์ กดแล้วเลือก Primary/Shared roots สำหรับแชตนั้นได้ทันที
- ถ้า Extension ยังยืนยัน Chat ID ไม่ได้ File/Terminal จะยังไม่มีสิทธิ์ใช้งาน จนกว่าจะเลือก approved roots ผ่าน Desktop เอง ค่า fallback นี้ไม่ถูกบันทึกถาวร และใช้สร้างสิทธิ์ให้ Prime หรือ Worker ไม่ได้
- Prime Run ใหม่รับ Workspace ของแชตเป็นขอบเขตสูงสุดของ Run ส่วน Worker รับขอบเขตเดิมหรือชุดที่แคบกว่าได้ แต่เพิ่ม root เองไม่ได้
- แถบด้านบนเรียงเป็น Update → Sub-agent → Language → Theme → Status → Power สวิตช์ Sub-agent ใช้ค่าระบบ Multi-agent เดิม ไม่ได้สร้างโหมดใหม่ซ้อนขึ้นมา
- สถานะ Connected / Not connected แสดงตาม connection state ล่าสุด และเปลี่ยนภาษาไทย/อังกฤษตามภาษาที่เลือก
- ถ้าเปลี่ยนชื่อ approved root ระบบจะรักษาสิทธิ์เดิมตาม root identity แต่ถ้าลบ root ออก สิทธิ์เก่าของแชตและ fallback จะถูกยกเลิก การลบแล้วเพิ่ม path เดิมใหม่จึงไม่ทำให้สิทธิ์เก่ากลับมาเอง
- Compact & Resume ย้าย Workspace ของแชตเดิมไปยังแชตใหม่ที่ระบบสร้างต่อให้แบบตรงตัว

### ขอบเขตความปลอดภัย

ถ้ายังไม่ได้เลือก Workspace ระบบจะไม่เปิดสิทธิ์ File/Terminal ให้ใช้งานตามปกติ

พาธจริงบนเครื่องจะอยู่ใน Desktop main process เท่านั้น ส่วน Extension และ Renderer รับเฉพาะ id กับชื่อ approved root ที่จำเป็นต่อ UI

ค่าที่โมเดลส่งมากับคำสั่งไม่สามารถขยายสิทธิ์ของแชต Prime หรือ Worker ได้ ระบบ Windows MXC ProcessContainer, fail-closed behavior และขั้นตอนเตรียม Windows host จาก v3.1.0 ยังทำงานเหมือนเดิม

### ติดตั้งบน macOS

ComGu v3.1.1 สำหรับ macOS รองรับ Mac ชิป Apple Silicon (M1/M2/M3/M4) และต้องใช้ macOS 12 Monterey หรือใหม่กว่า

ไฟล์รุ่นนี้ยังไม่ได้เซ็นด้วย Apple Developer ID และยังไม่ผ่าน notarization ของ Apple บางเครื่องจึงอาจขึ้นข้อความว่า `ComGu is damaged and can’t be opened` หลังดาวน์โหลด ทั้งที่ไฟล์ไม่ได้เสีย

1. ดาวน์โหลด `ComGu-macOS-arm64.dmg` จาก Release นี้
2. เปิดไฟล์ DMG แล้วลาก `ComGu.app` ไปไว้ในโฟลเดอร์ `Applications`
3. ถ้า macOS เปิดแอปไม่ได้หรือขึ้นข้อความด้านบน ให้เปิด Terminal แล้วรันคำสั่งนี้หนึ่งครั้ง

```bash
xattr -dr com.apple.quarantine /Applications/ComGu.app && open /Applications/ComGu.app
```

คำสั่งนี้ลบ quarantine attribute ที่ macOS ใส่ให้แอปที่ดาวน์โหลดจากอินเทอร์เน็ต แล้วเปิด ComGu ต่อทันที ถ้าอัปเดตเป็น ComGu รุ่นใหม่และ macOS ใส่ quarantine ให้ไฟล์ชุดใหม่ อาจต้องรันคำสั่งนี้อีกครั้ง

> ใช้วิธีนี้เฉพาะกับ ComGu ที่ดาวน์โหลดจาก GitHub Release ของ `Tanaboonnnnn/Com-gu` เท่านั้น ถ้ารุ่นถัดไปมี Developer ID signing และผ่าน Apple notarization แล้ว ขั้นตอนนี้จะไม่จำเป็นอีก

### หมายเหตุแต่ละแพลตฟอร์ม

- Windows x64 ยังเป็นแพลตฟอร์มหลักสำหรับ command confinement และมีทั้ง adversarial test กับ packaged outside-scope denial gate ใน release pipeline
- Windows ARM64 มี installer และ packaged runtime ของตัวเอง พร้อม native smoke test ใน release pipeline
- macOS ARM64 ผ่าน package smoke, bundle/Mach-O audit, archive verification และการเปิดแอปจริงบน runner ก่อนปล่อย Release
- Linux x64 และ ARM64 ผ่านทั้งการติดตั้งแพ็กเกจ DEB, GUI smoke ภายใต้ Xvfb และ AppImage smoke บน runner ของสถาปัตยกรรมเดียวกับไฟล์ที่ปล่อย
- macOS และ Linux ยังไม่มี Run command-confinement backend ที่พิสูจน์แล้ว Run-scoped commands จึง fail closed ส่วน File WorkspaceScope ยังใช้งานได้ตามปกติ
- Windows Desktop automation (`observe`, `computer`) ยังเป็นความสามารถระดับ Desktop และไม่ได้ถูกจำกัดด้วย Workspace roots
- ไฟล์ Release ยังไม่ได้เซ็น และ macOS artifacts ยังไม่ผ่าน notarization จึงอาจเจอ Windows SmartScreen หรือ macOS Gatekeeper ในการเปิดครั้งแรก
