# ComGu v3.1.3

## 3.1.3

ComGu 3.1.3 is a security and privacy hardening release. It tightens child-process credential isolation and browser-extension trust without changing the existing workspace, MXC confinement, exact-search, or tunnel architecture.

## Security

- Model-launched commands no longer inherit arbitrary credentials from the host process environment. Child processes receive a narrow OS/runtime allowlist, while protocol-specific credentials are added only by the subsystem that needs them.
- First-time browser companion pairing now requires explicit approval in the ComGu Desktop app. A different `chrome-extension://` identity cannot silently obtain or reuse the bridge bearer token.
- Paired extension trust can be revoked. Revocation invalidates both the approved origin and the bridge token.
- Existing approved companion extension refresh/reload remains automatic; the approval step is not repeated for the same trusted extension identity.
- Repository security gates now scan tracked source for high-confidence committed-secret patterns, unexpected runtime destinations, upstream-owner runtime residue, and floating GitHub Action refs. Production dependency auditing is also part of release verification.

## Privacy

- ComGu's expected app-managed outbound destinations are now documented and runtime-checked on the Windows x64 candidate. There is no product analytics, advertising telemetry, crash-reporting, webhook, or maintainer-owned telemetry endpoint.
- Goal Mode remains OFF by default. When enabled, its documented authored-user/final-assistant conversation subset is sent to OpenRouter for Goal decisions; this behavior is unchanged by 3.1.3.
- Linux package metadata no longer carries the previous upstream maintainer identity.

## Compatibility and unchanged behavior

- OpenAI Secure MCP Tunnel and Cloudflare Quick Tunnel remain supported with explicit subprocess environment boundaries.
- WorkspaceScope authority, Windows MXC command confinement, path virtualization, permission gates, loopback MCP/bridge binding, and fail-closed behavior are unchanged.
- Exact search is unchanged: this release contains no zvec or Smart Search behavior change.
- The release targets remain Windows x64, Windows ARM64, macOS ARM64, Linux x64, and Linux ARM64.
- macOS artifacts remain **unsigned** and **unnotarized**. Gatekeeper may warn on first launch.

## Runtime egress verification

The Windows x64 candidate was observed with idle, extension-only, OpenAI tunnel, and Goal/OpenRouter scenarios. Observed app-managed destinations matched the documented policy. Cloudflare was not exercised and is recorded as NOT RUN rather than inferred as passing. See `docs/security/2026-09-07-v3.1.3-runtime-egress-verification.md` for the evidence and capture limitation.

## macOS installation note

ComGu 3.1.3 for macOS supports Apple Silicon and requires macOS 12 Monterey or newer. The artifacts are unsigned and unnotarized. Download them only from the `Tanaboonnnnn/Com-gu` GitHub Release. If Gatekeeper blocks the app after you have verified the release source and checksum, remove the quarantine attribute for that installed app and open it again.
