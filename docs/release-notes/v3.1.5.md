# ComGu v3.1.5

## 3.1.5

ComGu 3.1.5 supersedes the unreleased 3.1.4 candidate and is a cross-platform reliability hotfix focused on Linux secure credential storage and browser-extension reachability. It keeps the v3.1.3 security boundaries intact while making Linux GNOME/libsecret startup deterministic, making credential failures diagnosable without exposing secrets, and replacing the flaky fixed-time Linux GUI release probe with readiness-driven validation.

## Linux credential storage

- On GNOME-like desktops (`GNOME`, Ubuntu GNOME, and Unity), ComGu asks Electron to use `gnome-libsecret` before safeStorage/OSCrypt initializes. An explicit user `--password-store` choice still wins, and KDE remains on Electron's own KWallet detection rather than guessing a KWallet generation.
- ComGu records sanitized provider evidence only: platform, async-availability, selected backend label, Linux ciphertext format (`v10`/`v11`/other), protection decision, and probe error category. Secret values, probe ciphertext, credential paths, bridge tokens, and extension origins are not logged.
- Linux `v10` ciphertext remains rejected because it represents Chromium's hard-coded-key fallback. There is no plaintext or `basic_text` fallback.
- Credential UI now distinguishes provider unavailable, rejected insecure Linux fallback, retryable credential-access failure, and positively unreadable encrypted stores. Ambiguous failures keep the existing encrypted blob untouched and block writes until secure storage is usable again.

## Browser companion reachability

- The extension now distinguishes Desktop transport absence from pairing blocked by secure credential storage, Desktop approval, explicit Disconnect, bridge protocol mismatch, or another retryable pairing failure.
- A Desktop process that disappears and later returns on the same supported loopback port can be rediscovered without reloading the service worker. A dead cached port can also be invalidated and rediscovered on another supported port (`8765`-`8769`).
- Held browser observations remain durable in the extension journal and are removed only after the Desktop app accepts the `/events` batch. Recovery does not clear the queue just to make the popup look healthy.
- Explicit Disconnect remains authoritative and health/retry paths cannot silently undo it.

## Release validation

- Linux DEB and AppImage GUI validation waits for actual startup proof (`app started`, `window loaded`, and `renderer state ready`) with a bounded 30-second deadline. The smoke runner now launches Xvfb/Electron in a dedicated POSIX process group and terminates the whole group before waiting for stream closure, preventing orphan Electron descendants from hanging release jobs.
- The release matrix remains Windows x64, Windows ARM64, macOS ARM64, Linux x64, and Linux ARM64.
- macOS artifacts remain **unsigned** and **unnotarized**. Keychain access can still depend on stable application signing identity; 3.1.5 preserves ambiguous ciphertext rather than resetting it automatically.

## Security boundaries unchanged

- `CALLER_IDENTITY_REQUIRED` stays fail-closed; no caller identity guessing was added.
- WorkspaceScope, Windows MXC command confinement, path virtualization, permission gates, loopback-only browser bridge binding, and exact-search behavior are unchanged.
- Child-process environment isolation remains allowlist-based. Host credentials and ambient `PSModulePath` are not restored.
- No zvec or ComGu Skill system is included.
