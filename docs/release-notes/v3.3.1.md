# ComGu v3.3.1

## 3.3.1

ComGu 3.3.1 removes the manual credential-key step from normal headless Linux CLI setup and makes folder authority switches visually consistent with the rest of the app.

## Highlights

- Fresh headless Linux installs can run `comgu setup --name <machine-name>` without manually exporting `COMGU_CREDENTIAL_KEY`.
- When no stronger Linux credential provider is available, setup creates `credentials.linux.key` in the selected profile with user-only `0600` permissions.
- systemd credentials, explicit environment injection, and Secret Service still take priority and do not cause a fallback file to be created.
- Existing credential vaults fail closed rather than being rebound if their previous secure source is missing.
- Clone preparation scrubs the Linux fallback key with the rest of machine credential state.
- Folder ON/OFF controls now use the same standard switch component as Permissions and Sub-agent controls.

## Headless Linux setup

```sh
curl -fsSL https://github.com/Tanaboonnnnn/Com-gu/releases/latest/download/install.sh | sh
comgu setup --name <machine-name>
comgu doctor
```

`comgu doctor` should report `Secure credentials: available` in a fresh shell without a manual environment export.

The profile fallback protects credential material from other local Unix users through file ownership and mode enforcement. It is not hardware-backed and does not protect against compromise of the same Unix account.

## CLI install

```sh
npm install -g comgu-cli
```

Linux one-line installer:

```sh
curl -fsSL https://github.com/Tanaboonnnnn/Com-gu/releases/latest/download/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://github.com/Tanaboonnnnn/Com-gu/releases/latest/download/install.ps1 | iex
```

All install channels verify the GitHub Release CLI payload against `SHA256SUMS.txt` before activation.

## Safety model

- Credential bootstrap does not widen filesystem, caller, terminal, pairing, or Desktop authority.
- Unsafe fallback-key ownership, permissions, or contents fail closed.
- Secrets are never embedded in the Linux service unit or printed in setup output.
- Semantic Desktop refs remain frame-free; raw coordinate actions still require a current authoritative frame.

## Release note

Automated CI covers Windows x64, macOS arm64 and Linux x64, while the release workflow packages Windows x64/ARM64, macOS arm64 and Linux x64/ARM64. Real graphical Linux validation on GNOME/KDE X11/Wayland, especially multi-monitor Wayland coordinate authority, has not been performed in this environment and is not implied by automated adapter/Xvfb tests.

Release binaries remain publisher-unsigned, and macOS artifacts remain unnotarized.
