# ComGu v3.3.1

## 3.3.1

ComGu 3.3.1 makes first-time headless Linux CLI setup self-contained: a Debian/Proxmox user no longer has to generate and export `COMGU_CREDENTIAL_KEY` manually when no stronger Linux credential backend is available.

## Highlights

- `comgu setup --name <machine>` now bootstraps a persistent user-private Linux credential wrapping key when systemd credentials, explicit environment injection and Secret Service are all unavailable.
- The fallback lives at `credentials.linux.key` inside the selected profile, is created exclusively with Node's cryptographic RNG, and is restricted to mode `0600`.
- Existing systemd credential, `COMGU_CREDENTIAL_KEY`, and Secret Service providers keep higher priority; setup does not replace or migrate a working credential source.
- Existing encrypted credential state whose original provider is unavailable fails closed instead of silently creating a replacement key.
- The fallback key is validated as a regular file owned by the current Unix user, with no group/world permission bits and canonical Base64 decoding to exactly 32 bytes.
- Concurrent setup calls cannot replace an already-created key.
- `machine prepare-clone --yes` removes the fallback key alongside the rest of machine-specific credential state.
- The Linux user service contains no secret value or credential environment variable; a restarted service reads the validated profile fallback directly.

## Headless Linux setup

```sh
curl -fsSL https://github.com/Tanaboonnnnn/Com-gu/releases/latest/download/install.sh | sh
comgu setup --name tian-proxy
comgu doctor
```

A fresh headless host should report `Secure credential source: available` during setup and `Secure credentials: available` from `comgu doctor` without any manual shell export.

The profile fallback is user-private filesystem protection, not hardware-backed storage and not protection against compromise of the same Unix account.

## Safety model

- Credential bootstrap changes Linux credential-at-rest handling only; enabled-root authority, caller identity, terminal ownership, pairing, MCP surface separation, Windows command confinement and Wayland frame authority are unchanged.
- Invalid ownership, permissions or key material fail closed and are never silently overwritten.
- Key material is never printed in CLI output, connector metadata, process arguments or the generated systemd unit.

## Release note

Automated CI covers Windows x64, macOS arm64 and Linux x64, while the release workflow packages Windows x64/ARM64, macOS arm64 and Linux x64/ARM64. Real graphical Linux validation on GNOME/KDE X11/Wayland, especially multi-monitor Wayland coordinate authority, has not been performed in this environment and is not implied by automated adapter/Xvfb tests.

Release binaries remain publisher-**unsigned**, and macOS artifacts remain **unnotarized**. On macOS, use the documented manual Gatekeeper override only for artifacts downloaded from the official ComGu GitHub Release, and verify `SHA256SUMS.txt` before installing.
