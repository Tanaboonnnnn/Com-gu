# ComGu v3.3.2

## 3.3.2

ComGu 3.3.2 fixes ChatGPT project/GPT chat recognition in the companion extension and completes npm Trusted Publishing for the CLI release channel.

## Fixed

- The extension now recognizes conversation URLs whose chat id is the final `/c/<id>` segment under prefixed ChatGPT routes such as `/g/<project-or-gpt>/c/<id>`.
- Already-open project chats can be matched to the correct conversation instead of being treated as missing and opening a duplicate fallback chat.
- Ordinary `/c/<id>` routes and the supported legacy `chat.openai.com/c/<id>` form remain compatible.

## Release infrastructure

- `comgu-cli` publishing uses npm Trusted Publishing with GitHub Actions OIDC; no long-lived npm publish token is required.
- The npm publisher is bound to `Tanaboonnnnn/Com-gu` and `.github/workflows/publish.yml` with direct publish permission.
- Public npm installs still bootstrap the same checksummed GitHub Release CLI payload used by the one-line installers.

## CLI install

```sh
npm install -g comgu-cli
```

Linux one-line installer:

```sh
curl -fsSL https://github.com/Tanaboonnnnn/Com-gu/releases/latest/download/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://github.com/Tanaboonnnnn/Com-gu/releases/latest/download/install.ps1 | iex
```

## Safety model

- Conversation identity is extracted only from an explicit final `/c/<id>` route segment; project/GPT slugs are never treated as conversation ids.
- Workspace/enabled-root authority, caller identity, pairing, terminal ownership, command confinement, and Desktop/Wayland frame authority are unchanged.
- Semantic Desktop refs remain frame-free; raw coordinate actions still require a current authoritative frame.

## Release note

Automated CI covers Windows x64, macOS arm64 and Linux x64, while the release workflow packages Windows x64/ARM64, macOS arm64 and Linux x64/ARM64. Real graphical Linux validation on GNOME/KDE X11/Wayland, especially multi-monitor Wayland coordinate authority, has not been performed in this environment and is not implied by automated adapter/Xvfb tests.

Release binaries remain publisher-unsigned, and macOS artifacts remain unnotarized.
