# ComGu 3.1.3 Security & Privacy Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task inline. Do **not** dispatch subagents unless the user explicitly changes the standing no-subagents preference. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden ComGu so model-launched processes cannot inherit unrelated host credentials, the browser bridge cannot silently trust an arbitrary Chrome extension, outbound destinations stay explicit and reviewable, security/privacy checks become release gates, and the v3.1.3 release removes remaining upstream-owner metadata residue without weakening existing workspace/MXC/tunnel protections.

**Architecture:** Preserve the existing loopback-only MCP and browser-bridge design, but tighten two trust boundaries. First, replace broad process-environment inheritance with a small OS-aware base allowlist plus explicit per-launch overrides. Second, turn browser pairing into a durable, user-approved extension-origin binding: the first extension identity must be approved in Desktop, while the already-approved identity continues to reconnect/reload automatically. Add repository-level egress and secret-pattern invariants plus dependency auditing so later changes cannot quietly reintroduce new destinations or credential leaks.

**Tech Stack:** Electron 43, TypeScript 7, Node.js 22+, MV3 Chrome extension JavaScript, Vitest, GitHub Actions, Electron `safeStorage`, Node `http`, existing ComGu release/packaging scripts.

## Security invariants for this release

The implementation must preserve all of these while completing the tasks below:

- MCP remains bound to `127.0.0.1` only, with per-surface random path tokens, host/origin validation and body limits.
- The browser bridge remains bound to `127.0.0.1:8765-8769` only and never gains filesystem or command-execution routes.
- MXC command confinement, workspace-scope authority, virtual paths, permission gates and exact-search behavior are unchanged.
- OpenAI tunnel and Cloudflare tunnel remain supported. Their subprocesses receive only the environment they explicitly need.
- Goal Mode remains opt-in and continues to be the only app-managed path that sends recorded conversation text to OpenRouter.
- Updater/extension recovery remains pinned to `Tanaboonnnnn/Com-gu`; no runtime endpoint may point at `totec448-spec/chat-on-steroids`.
- Existing extension auto-refresh/reload remains automatic after the initial pairing identity has been approved.
- No zvec work, ComGu skill system, or ComGu-qwen work belongs in this release.

- [ ] **Step 1: Implement an OS-aware inherited-environment allowlist**

Create `src/main/child-env-policy.ts` with a narrow base policy. Preserve variables needed for ordinary command execution, locale, temp directories and proxies, but do not copy arbitrary provider/CI/cloud credentials:

```ts
const COMMON = new Set([
  'PATH', 'HOME', 'TMPDIR', 'TEMP', 'TMP', 'LANG', 'LANGUAGE', 'TERM',
  'HTTP_PROXY', 'HTTPS_PROXY', 'NO_PROXY', 'ALL_PROXY'
]);

const WINDOWS = new Set([
  'SYSTEMROOT', 'WINDIR', 'COMSPEC', 'PATHEXT', 'USERPROFILE',
  'HOMEDRIVE', 'HOMEPATH', 'APPDATA', 'LOCALAPPDATA', 'PROGRAMDATA',
  'PROGRAMFILES', 'PROGRAMFILES(X86)', 'PROGRAMW6432'
]);

const POSIX_PREFIXES = ['LC_', 'XDG_'];

export function inheritedChildEnvironment(
  source: NodeJS.ProcessEnv = process.env,
  platform: NodeJS.Platform = process.platform
): NodeJS.ProcessEnv {
  const out: NodeJS.ProcessEnv = {};
  for (const [rawKey, value] of Object.entries(source)) {
    if (value === undefined) continue;
    const key = rawKey.toUpperCase();
    const allowed =
      COMMON.has(key) ||
      (platform === 'win32' && WINDOWS.has(key)) ||
      (platform !== 'win32' && POSIX_PREFIXES.some((prefix) => key.startsWith(prefix)));
    if (allowed) out[rawKey] = value;
  }
  return out;
}
```

Do not include `GITHUB_*`, `AWS_*`, `AZURE_*`, `GOOGLE_*`, `NPM_TOKEN`, provider API keys, SSH-agent variables, CI tokens or generic `*_TOKEN`/`*_SECRET` values unless a later subprocess adds one explicitly for its own protocol.

- [ ] **Step 2: Implement the pairing state module**

Create `src/main/bridge-pairing.ts` with a memory-only pending origin and durable approved origin:

```ts
let pendingOrigin: string | null = null;

export async function extensionPairingView(): Promise<ExtensionPairingView> {
  return {
    approvedOrigin: (await getSecret('approvedExtensionOrigin')) || null,
    pendingOrigin
  };
}

export async function requestExtensionPairing(origin: string): Promise<'approved' | 'pending'> {
  const approved = await getSecret('approvedExtensionOrigin');
  if (approved === origin) return 'approved';
  pendingOrigin = origin;
  return 'pending';
}

export async function approvePendingExtensionOrigin(): Promise<void> {
  if (!pendingOrigin) throw new Error('No extension is waiting for approval');
  await setSecret('approvedExtensionOrigin', pendingOrigin);
  pendingOrigin = null;
}

export async function revokeExtensionOrigin(): Promise<void> {
  await setSecret('approvedExtensionOrigin', '');
  await setSecret('bridgeToken', '');
  pendingOrigin = null;
}
```

Validate that the origin exactly matches `^chrome-extension://[a-p]{32}$` before it can become pending or approved. Do not accept prefixes, paths, query strings or non-Chromium schemes.

- [ ] **Step 4: Change `/pair` from silent trust to pending approval**

The route must follow this order:

```ts
if (route === '/pair' && req.method === 'POST') {
  if (!origin) return json(res, 403, { error: 'extension_origin_required' }, origin);
  if (!protocolCompatible(req)) return json(res, 426, { error: 'incompatible_extension', bridge: BRIDGE_PROTOCOL, version: APP_VERSION }, origin);
  if (rateLimited()) return json(res, 429, { error: 'rate_limited' }, origin);

  const pairing = await requestExtensionPairing(origin);
  if (pairing !== 'approved') {
    changed();
    return json(res, 403, { error: 'pairing_required' }, origin);
  }

  const token = randomBytes(32).toString('base64url');
  await setSecret('bridgeToken', token);
  changed();
  return json(res, 200, { token }, origin);
}
```

Every authenticated route must additionally require that its request Origin equals the approved origin whenever an Origin header is present. A stolen bearer token from another extension origin must not be sufficient.
