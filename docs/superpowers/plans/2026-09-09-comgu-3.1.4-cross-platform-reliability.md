# ComGu 3.1.4 Cross-Platform Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Project constraint:** ComGu work for this repository must not dispatch subagents. Choose `superpowers:executing-plans` and execute inline in one session/worktree.

**Goal:** Ship a v3.1.4 hotfix that restores reliable Linux OS-backed credential storage and browser-extension-to-Desktop reachability, keeps macOS/Windows behavior fail-closed and regression-safe, and removes the flaky fixed-time Linux GUI release probe without weakening any v3.1.3 security boundary.

**Architecture:** Treat this as three independently gated reliability tracks: (A) OS credential-provider diagnosis/classification, (B) extension loopback discovery/pairing self-healing, and (C) cross-platform release validation. Do not assume the Linux credential symptom and extension reachability symptom share one root cause; instrument each boundary first, then implement only the branch supported by evidence. Keep all secrets in Electron `safeStorage`, keep the extension journal durable until Desktop ACK, and keep user Disconnect, exact extension-origin approval, caller identity, WorkspaceScope, MXC, and permission checks authoritative.

**Tech Stack:** Electron 43.4.1, TypeScript, Vitest 4, Chrome MV3 extension JavaScript, Node 22 packaging scripts, electron-builder 26, GitHub Actions, Linux Secret Service/KWallet, macOS Keychain, Windows DPAPI.

## Confirmed baseline and incident evidence

This plan starts from merged/released v3.1.3, not from the old feature branch.

1. `main` currently points at merge commit `a70b682b358fe4a6dff229b0e1f8cba1798efd19`.
2. v3.1.3 is already published, so this work must become v3.1.4. Never move or replace tag `v3.1.3`.
3. Linux user reproduction is Ubuntu 24.04, `ubuntu:GNOME`, Wayland, valid session D-Bus, `gnome-keyring-daemon --components=pkcs11,secrets`, `libsecret-1-0`, and a successful `secret-tool store` -> `secret-tool lookup` round trip. Despite that, packaged ComGu displays `Secure credential storage is unavailable` and disables API-key input.
4. Electron 43.4.1 async safeStorage uses `os_crypt_async` and requests `kEncryptSyncCompat`. Chromium's `PosixKeyProvider` emits `v10` with the public `peanuts` key; `FreedesktopSecretKeyProvider` emits `v11`. Therefore ComGu must continue rejecting actual `v10` ciphertext. The open question is why Electron falls back to `PosixKeyProvider` on a machine where Secret Service works outside Electron.
5. Extension reproduction: ChatGPT tab detection, recording, Chat ID and Request ID are green, but `Reaching the app` is blocked, the service worker reports held observations (example: `43 held`), and extension/page reload does not recover Desktop reachability.
6. v3.1.3 release CI had one Linux x64 DEB Xvfb launch failure while package/native smoke passed; the same step passed on Linux arm64 and later a v3.1.3 release was published. Treat the fixed 12-second timeout as a test-quality problem until runtime evidence proves a product defect.

## Non-negotiable invariants

- Never store API keys or bridge credentials in plaintext, `basic_text`, logs, renderer state, config, or extension content scripts.
- Never accept Linux `v10` ciphertext as secure storage.
- Never delete/overwrite `secrets.bin` after an ambiguous decrypt/provider failure.
- Never silently unpair or re-pair a different extension identity.
- Approval stays bound to the exact reviewed `chrome-extension://` origin.
- Explicit user Disconnect remains authoritative; health alarms and retries may not undo it.
- Do not auto-replay non-idempotent stale-document mutations.
- Held browser observations stay queued until Desktop ACK; recovery must not drop or relabel them.
- Do not weaken `CALLER_IDENTITY_REQUIRED`, WorkspaceScope, MXC, permission gates, or path virtualization.
- Do not reintroduce broad child-process environment inheritance or host `PSModulePath`.
- Do not add zvec, a Skill system, or unrelated feature work.
- Windows x64, Windows arm64, macOS arm64, Linux x64 and Linux arm64 remain release targets.

### Task 6: Implement a single-flight extension discovery/recovery state machine

- [ ] **Step 1: Add a single in-flight discovery promise**

Use this shape:

```js
let discoveryWork = null;

function discoverSingleFlight(force = false) {
  if (!discoveryWork) {
    discoveryWork = discoverNow(force).finally(() => {
      discoveryWork = null;
    });
  }
  return discoveryWork;
}
```

If a forced request arrives while a non-forced discovery is in flight, do not launch five additional parallel `/hello` calls. The current scan completes; a failed result clears trust so the next call can force a fresh scan.

- [ ] **Step 2: Make failed transport invalidate cached port authority**

On fetch/network failure to a trusted port:

```js
portCheckedAt = 0;
portCompatible = null;
appVersion = null;
appProtocol = null;
```

Clear/persist `port` only after the trusted port actually fails; do not discard a healthy port on an application-level 4xx response.

- [ ] **Step 3: Force rediscovery from the right triggers**

Use forced rediscovery when all conditions are true:

```text
not explicitly disconnected
and Desktop transport was unreachable
and there is work that benefits from recovery (journal/outbox/status user retry)
```

Required triggers:

```text

retry alarm while journal or ACK outbox is held
```
