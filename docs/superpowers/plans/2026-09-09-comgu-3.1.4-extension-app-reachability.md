# ComGu 3.1.4 Extension App Reachability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Project constraint:** no subagents for ComGu. Use `superpowers:executing-plans` inline.

**Goal:** Make the MV3 extension recover from Desktop disappearance/restart/port change without page or extension reload, while preserving held observations, exact-origin pairing approval, and explicit user Disconnect.

**Architecture:** Keep `extension/background.js` as the only network owner. Refactor discovery into one single-flight state machine that distinguishes transport reachability from authentication/pairing state; on transport failure it invalidates only cached reachability evidence, scans the fixed loopback port set again, and then reuses the existing pairing and journal-drain paths. The popup renders the worker's reason code rather than treating every non-ready state as `appUnreachable`.

**Tech Stack:** Chrome MV3 service worker, `chrome.storage.local`, `chrome.storage.session`, Vitest VM harness in `test/extension.test.ts`, Desktop loopback bridge in `src/main/bridge.ts`.

---

## Incident reproduction to preserve

The observed popup state is:

```text
ChatGPT tab                 OK
Recording this chat         OK
Chat ID                     OK
Request ID                  OK
Reaching the app            blocked
Picked up                   > 0
Sent to app                 held
App processed               off
```

Reloading the ChatGPT page or extension does not restore Desktop reachability. The service-worker journal must be treated as valuable durable browser-session data; recovery may not clear it merely to make the popup green.

## Security and correctness invariants

- Network destinations remain exactly loopback ports 8765-8769.
- Content scripts never receive the bearer token.
- `chatgpt.com` does not call authenticated Desktop routes directly.
- Unknown extension origin still requires exact Desktop approval.
- `Disconnect` remains durable and alarms/status polling cannot undo it.
- A 401 may rotate/re-pair only through the existing approved-identity path.
- A 4xx application response is not the same as transport absence.
- Held observations are removed only after Desktop accepts the `/events` batch.
- No synthetic resend of non-idempotent page mutations.

### Task 4: Add one single-flight discovery operation

**Files:**
- Modify: `extension/background.js`
- Test: `test/extension.test.ts`

- [ ] **Step 1: Add process-local single-flight state beside existing pairing/drain single-flights**

```js
let discoveryWork = null;
let rediscoveryRequested = false;
```

- [ ] **Step 2: Split the current discovery body into `discoverNow(force)`**

`discoverNow()` remains responsible for scanning only `PORTS`, validating `/hello`, version/protocol capture, and persisting the selected port.

- [ ] **Step 3: Add the shared wrapper**

```js
function discover(force = false) {
  if (force && discoveryWork) rediscoveryRequested = true;
  if (!discoveryWork) {
    discoveryWork = (async () => {
      let result = await discoverNow(force);
      if (rediscoveryRequested) {
        rediscoveryRequested = false;
        result = await discoverNow(true);
      }
      return result;
    })().finally(() => {
      discoveryWork = null;
    });
  }
  return discoveryWork;
}
```

This preserves a forced retry that arrives during a non-forced scan without launching parallel five-port scans.

## Self-review

- The plan uses the repository's existing `loadWorker`, `FakeStorageArea`, `journalOf(session)`, `worker.send()`, `worker.fireAlarm()` and storage data; it does not introduce imaginary test helpers.
- Every transport-recovery step preserves explicit Disconnect and pairing approval.
- No step clears the browser journal as a recovery mechanism.
- A reachable Desktop with secure-storage failure is intentionally distinct from app absence, which directly covers the reported screenshot.
- Discovery remains bounded to the five existing loopback ports and keeps the healthy-port trust window.
- Implementation is independent of the Linux safeStorage root cause; if secureStorage is the upstream pairing blocker, the popup will finally report that accurately rather than disguising it as transport absence.
